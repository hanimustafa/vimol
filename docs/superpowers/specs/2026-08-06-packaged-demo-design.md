# Ship the C60 demo inside the package

## Problem

`vimol` with no file argument opens the bundled C60 demo — but only from a
checkout or editable install. `_default_demo_path()` in
[`src/vimol/app.py`](../../../src/vimol/app.py) resolves the demo as
`<repo>/examples/c60.xyz`, three directories up from `app.py`. `examples/`
sits next to `src/`, not inside the installed package, so on a real
`pip install vimol` that path never exists. The very first thing a new user
types — `vimol`, no arguments — falls back to `--help` instead of showing
them a molecule.

## Design

**`examples/c60.xyz` stays the canonical source.** It's already referenced
directly by `examples/inset.py` and `examples/embed_demo.py` and by the
README, and it's already regenerated deterministically by
`examples/build_examples.py`. Nothing about that changes.

**A packaged copy is added at `src/vimol/data/c60.xyz`**, generated by the
same `buckyball()` call in `build_examples.py` that writes
`examples/c60.xyz` — one geometry computation, two `write_xyz` calls, so the
two files can never drift out of sync as long as the script is re-run when
either changes. This copy is included as `setuptools` package-data, so it
ships in both the wheel and sdist and survives a normal `pip install`.

`_default_demo_path()` prefers the packaged copy and falls back to the
checkout path:

1. `<package_dir>/data/c60.xyz` (works on any install, editable or not)
2. `<repo>/examples/c60.xyz` (works in a checkout even before the packaged
   copy has been generated, e.g. right after cloning before running
   `build_examples.py`)
3. `None` (falls back to `--help`, as today)

### Changes

1. **`examples/build_examples.py`** — `buckyball()` writes the same atom
   list to `examples/c60.xyz` and `src/vimol/data/c60.xyz`.
2. **`pyproject.toml`** — `[tool.setuptools.package-data]` for `vimol` gains
   `"data/c60.xyz"` alongside the existing `"py.typed"`.
3. **`src/vimol/app.py`** — `_default_demo_path()` tries the packaged path
   first, then the checkout path; docstring updated to describe both.
4. **`scripts/build-pypi-artifacts`** — after `build`, assert the built
   wheel contains `vimol/data/c60.xyz`, next to the existing `twine check`
   and install-and-smoke-test steps. Fails loudly if the data file is ever
   dropped from packaging.
5. **`tests/test_editing.py`** — a new test that simulates "installed
   wheel, no `examples/` directory around" by monkeypatching
   `os.path.exists` so only the packaged path resolves, and asserts
   `_default_demo_path()` still finds the demo. The existing
   `test_default_demo_path_resolves_to_bundled_c60` and
   `test_cli_with_no_file_uses_demo_default_not_help` are unaffected — they
   exercise the checkout path, which keeps working.

### Out of scope

- No change to how `examples/*.xyz` files are used by `inset.py`,
  `embed_demo.py`, or the README.
- No change to any other example file (`water.xyz`, `methane.xyz`, etc.) —
  only C60 is ever the zero-arg default.
- No `importlib.resources` migration — a plain path join next to
  `__file__` is enough here and matches how `py.typed` is already handled.
